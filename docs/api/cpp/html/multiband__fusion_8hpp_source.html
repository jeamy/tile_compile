3// Controlled multi-band reconstruction --- milestone M6 of the CFA-forward-
4// drizzle plan (docs/AQMH/aqmh_cfa_forward_drizzle_multiband_implementierungs
5// plan_de.md, sections 14.2-14.3).
6//
7// This is the whole-image IN-MEMORY REFERENCE path (plan 14.7 allows it for
8// tests). It combines frequency bands of four profiles that share the same
9// accepted CFA samples but different quality weights:
10// U = Uniform control -> the coarse residual C_U,L
11// R = Raw forward drizzle -> the blend base of EVERY band difference
12// F = Fine profile (scale-0 Q) -> the finest detail band D1
13// M = Medium profile (scale-1 Q) -> D2
14//
15// Band assignment for `levels = L` (plan 14.3):
16// L=1: D1<-F, coarse C1<-U
17// L=2: D1<-F, D2<-M, coarse C2<-U
18// L>=3: D1<-F, D2<-M, D3..DL<-R, coarse CL<-U
19// Blend (plan 14.3):
20// D_out,j = D_R,j + alpha_j * (D_profile,j - D_R,j)
21// X_out = C_U,L + sum_j D_out,j
22// For a band whose profile source is R, alpha_j is ineffective. An invalid
23// detail profile forces alpha_j = 0 at that pixel; a missing Raw band makes
24// the whole multi-band pixel invalid (plan 14.2). The adaptive alpha of
25// plan 14.4 is a LATER batch --- here alpha is caller-provided.

106// Runs the full plan-14 pipeline on whole-frame profile planes:
107// adaptive alpha (14.4) -> local energy guard (14.5) -> B3 alpha smoothing
108// (14.7) -> per-channel band blend (14.3).

110// guard works on the fixed working luminance 0.25R+0.5G+0.25B (D_L for MONO).

127// ---- Streamed (row-striped) fusion, verified bit-exact vs. fuse_multiband ---
128
129// Vertical halo (internal px) a fusion stripe must fetch on each side of its
130// committed core rows so that every committed pixel is byte-identical to the
131// whole-frame fuse_multiband result. Covers: cumulative a-trous vertical
132// reach over all `levels` (2*(2^levels - 1)), the widest energy-guard MAD
133// window (energy_guard_window_radius(levels)) and the B3 alpha-smoothing
134// reach (2). Deliberately conservative --- the guard only runs on bands 1-2,
135// so the strict lower bound is smaller; over-padding only costs work.

138// Same contract and result as fuse_multiband(), computed one row-stripe of
139// `chunk_rows` committed rows at a time (each stripe internally runs
140// fuse_multiband on its core +/- multiband_fusion_halo_rows() and commits
141// only the core). Byte-identical to fuse_multiband() on every supported
142// pixel EXCEPT, by construction, where a 4-connected alpha-support component
143// is joined only by a path that leaves a stripe's fetched region (the B3
144// flood fill is the one non-local step); such divergence is bounded and
